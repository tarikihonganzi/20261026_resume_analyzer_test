# マッチング評価

採用担当者が、1 人の応募者の職歴書（PDF・Word・Excel・PowerPoint・テキスト。複数の書類を合わせて）を、選んだ条件（資格・スキル・経験年数）に照らして評価する、ローカルで動く Web アプリです。

- 条件ごとの有無・年数を LLM が読み取り、**マッチ度合いはコードで計算**し、最終スコアと根拠つきの評価文を LLM が作ります。
- 結果には、条件ごとの判定（クリア・NG・不明）と、根拠（職歴書の引用）が付きます。引用が原文に見つからないときは「原文で確認できず」と表示します。
- 個人利用です。サーバーは職歴書も評価結果も保持しません（保存するのは、条件セットと設定だけです）。
- 本結果は判断材料です。最終的な判断は人が行ってください。

仕様は [docs/spec.md](docs/spec.md)、実装計画は [docs/implementation-plan.md](docs/implementation-plan.md)、作業の状況は [Kanban.md](Kanban.md) にあります。

## 必要なもの

| もの | 内容 |
|---|---|
| OS | Windows（開発・動作確認は Windows 11） |
| [uv](https://docs.astral.sh/uv/) | `winget install --id=astral-sh.uv -e`。入れたあとは、新しいターミナルを開く。Python 3.14 は uv が用意する |
| Node.js | 24.x（npm を使う） |
| OpenAI API | API キー（社内のエンドポイントなら、そのベース URL も）。評価のときだけ必要 |

## セットアップ

```powershell
npm run setup                            # 依存の導入（ルート・frontend・e2e の npm ci、backend の uv sync）
npm run install:browsers --prefix e2e    # E2E を実行する場合だけ（Chromium の取得）
```

## 起動

```powershell
npm run start
```

フロントをビルドし、FastAPI が画面と API を **1 つのプロセス**で配信します。ブラウザで <http://127.0.0.1:8000> を開きます。`127.0.0.1` だけで待ち受けるので、他の PC からは開けません。止めるときは `Ctrl+C` です。

開発するときは、`npm run dev`（バックエンド 8000 と Vite 5173。画面は <http://127.0.0.1:5173>）を使います。

### 初回の設定

画面右上の「設定」で、API キー・ベース URL・モデル名を登録します（保存先は `data/config.json`。所有者だけが読み書きできる設定で、Git には入りません）。「接続テスト」で、保存する前に確かめられます。

- API キーは、画面にはマスク（末尾 4 文字）でしか表示されません。変更するときだけ入力します。
- 環境変数 `OPENAI_API_KEY`・`OPENAI_BASE_URL`・`OPENAI_MODEL` は、設定ファイルにまだ値がないときの初期値です。設定ページで保存した値が優先されます。
- 変更は、アプリを再起動せずに、次の評価から反映されます。

## 使い方

1. **① 条件** … プリセット（75 件）から、条件ごとに「使わない・任意・必須」を選びます。年数の条件は最低年数も入れます。自由記述の条件（補足説明つき）も足せます。条件セットとして保存し、あとで読み込めます。
2. **② 書類** … 1 人の応募者の書類を、ファイル（複数可）のドラッグ＆ドロップか、テキストの貼り付けで、合わせて最大 5 件まで渡します。選んだ直後に 1 件ずつ検証し、「アップロード済みの書類」の一覧に並べます。間違えたファイルは、削除ボタンで取り消せます。読めないファイルは、その場でエラーになります。
3. **③ 結果** … 最終スコア（AI 算出）とマッチ度合い（スキルの充足度）、必須条件の状況、AI の評価コメント（総評・良かった点・悪かった点）、条件別の判定（必須・任意 × クリア・NG）が出ます。根拠（職歴書の引用）は、「根拠を見る」で開きます。「別の応募者を評価」で、条件を残したまま次の応募者に進めます。

評価の途中で「キャンセル」できます。

## デモモード（他の PC から開く）

デモのときだけ、同じネットワークの他の PC から開けるようにできます。

```powershell
npm run start:demo
```

起動時に、他の PC から開くための URL が表示されます。**同じネットワークの誰でも、設定の変更と評価（API の費用がかかります）ができる**ので、デモが終わったら止めてください。認証などの追加の保護はありません（仕様 13.1 #26）。

## テスト

| コマンド | 内容 |
|---|---|
| `npm run check` | lint・型検査・バックエンドとフロントのテスト。**ネットワークと API 費用を使いません。** コミットの前に実行します |
| `npm run coverage` | カバレッジの測定（バックエンドは行と分岐の 99%、フロントは文 99%・分岐 95%）。しきい値を下回ると失敗します。詳しい表は `coverage/` に出ます |
| `npm run e2e` | Playwright。偽の LLM（`APP_LLM_MODE=fake`）で、開発用とは別のポート（API 8100・画面 5273）にサーバーを自動で起動して通します。API 費用はかかりません |

実 API のテスト（`backend/tests/live`）は、費用がかかるので、通常は実行しません。

テスト用の職歴書は、すべて架空のものを `backend/tests/fixtures/resume_factory.py` で生成します。実在の個人情報は使いません。

## 環境変数

| 変数 | 内容 |
|---|---|
| `OPENAI_API_KEY`・`OPENAI_BASE_URL`・`OPENAI_MODEL` | 設定の初期値（設定ページで保存した値が優先） |
| `APP_DATA_DIR` | データの置き場所（既定は、リポジトリの `data/`） |
| `APP_LOG_DIR`・`APP_LOG_LEVEL` | ログの出力先（既定は、リポジトリ直下の `log/`）と、レベル（既定は INFO）。`log/` に、その日の日付のファイル（`2026-10-25.log` など）で残る。30 日分を残し、古いものは消える |
| `APP_PORT` | `npm run start` の待ち受けポート（既定 8000） |
| `APP_STATIC_DIR` | 配信する、ビルド済みのフロント（既定は `frontend/dist`。なければ API だけ） |
| `APP_ALLOW_REMOTE` | `1` のときだけ、他の PC からのアクセスを許す。`npm run start:demo` が指定する |
| `APP_LLM_MODE`・`APP_FAKE_DELAY_SEC` | `fake` で、偽の LLM を使う（テスト・E2E 用） |

## 個人情報の扱い

- 職歴書の内容は、サーバーのディスクにもログにも残しません。評価のたびに、ブラウザから送り直します（再読み込みすると、画面の状態は消えます）。
- ログ（`log/2026-10-25.log` のような、日付のファイル）には、リクエスト ID・所要時間・件数・トークン使用量・エラーの種類だけを記録します。API キーや、書類の名前・内容は、記録しません。
- LLM への送信は `store=false` です。PDF は、手元でテキストにせず、そのまま LLM に渡します。
- ローカルの API は `127.0.0.1` だけで待ち受け、`Host` と `Origin` を検査します（CORS は無効）。
