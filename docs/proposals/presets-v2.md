## 1. 目的

1. 条件に、**任意の補足説明（自然言語）** を付けられるようにする。自由記述の条件はもちろん、既存のプリセット（「品質管理」「原価管理」など）にも、「何を、その条件として数えるか」を書いておく。LLM が判定するときの基準にする。
2. 現場監督、現場に近い事務、施工図を扱う人に必要なスキルを調べ直し、プリセットの素案を見直す。

## 2. 補足説明（`description`）の設計

### 2.1 使い方

- 条件に、任意の項目 `description`（補足説明。省略可）を足す。
- **抽出（ステップ 1）の入力の「条件の一覧（JSON）」に、`description` を含める。** システム指示に「`description` がある条件は、その定義に従って判定する。定義に当てはまらないものは、数えない」と書く。
- 最終評価（ステップ 3）にも、同じ `description` を渡す。

### 2.2 「Structured Output の各項目の description」について

ご希望は「Structured Output の各項目の description に使いたい」でした。仕組み上、次のとおりです。

| 方式 | 内容 | 評価 |
|---|---|---|
| **A. 入力の条件一覧に含める（推奨）** | スキーマは固定（`results[]` の各要素に `condition_id`）。条件ごとの定義は、入力の JSON で渡す | 仕様 9 章の決定（条件ごとにスキーマを作らない）と整合。スキーマの検査・OpenAPI の型・ゴールデンテストが、そのまま使える。LLM は、条件の `description` を、スキーマの `description` と同じように参照できる |
| B. 条件ごとにスキーマを動的に作り、各条件を専用のプロパティにして `description` を付ける | 条件ごとに別のプロパティ（例: `cond_<id>`）を持つスキーマを、リクエストのたびに作る | スキーマの `description` に直接入る。ただし、**strict の制約**（プロパティ数・深さ）、**スキーマの変化によるキャッシュの不利**、**テストの複雑化**、LLM の出力の順序・欠落の検証が増える。効果が A と大きく変わるとは言えない |

**推奨は A。** 補足説明は、LLM から見て、スキーマの `description` と同じ「指示の文」として働く。

### 2.3 画面

- 自由記述の追加・編集モーダルに、「補足説明（任意）」の複数行の入力欄を足す。入力例を、プレースホルダーで示す（例: 「耐震診断の業務で、診断報告書の作成までを担当した経験」）。
- 一覧の各行は、条件名の下に、補足説明を、小さい文字（`secondary`）で表示する（長い場合は、2 行で折り、全文はツールチップ）。プリセットの補足説明も同様に表示する。
- プリセットの補足説明は、`catalog.json` に書く（利用者が、ファイルを直接編集して直せる）。画面からの編集は、MVP では行わない。
- 条件セットには、自由記述の補足説明も含めて保存する。

### 2.4 変更の範囲

| 対象 | 変更 |
|---|---|

## 3. 調べたこと

調査日: 2026-10-25。Web 検索の要約から、**確認できたこと**と、**確認できなかったこと**を分けて書く。

### 3.1 現場監督（施工管理）

- 施工管理の中心は「四大管理」（原価・工程・品質・安全）。現場監督と施工管理は、企業によって呼び方が異なり、明確な線引きはない（[boxil](https://boxil.jp/mag/a4266/)、[バイトル](https://www.baitoru.com/lp/foreman/)、[ONE CAREER](https://plus.onecareer.jp/articles/1854) など）。
- 国家資格の施工管理技士は、資格がなくても始められるが、一定規模以上の現場では配置が義務付けられ、需要が高い。土木・建築・電気・管など、専門分野で分かれる。
- 求められる力: スケジュール管理（工程表の作成〜日々の進捗確認）、職人・業者との調整（コミュニケーション、リーダーシップ）。
- 厚生労働省の職業情報では、総合工事業の現場生産管理は、**原価・品質・工程・安全衛生・環境**を含めた計画の立案と運用管理（関連資格: 一級施工管理技士、一級建築士など）（[厚労省](https://www.mhlw.go.jp/content/11800000/000593910.doc)）。→ 「環境管理」を足す根拠。
- 公共工事の施工管理基準では、施工管理は、**工程管理・出来形管理・品質管理と、工事写真**で構成される。測定・試験の結果は、その都度、管理図表に記録する。施工計画書は、品質管理の体制まで具体化することが検査で見られる（[長崎県](https://www.doboku.pref.nagasaki.jp/siyousyo/sekoukanri/sekoukanrikijyun(H26.4).pdf)、[埼玉県](https://www.pref.saitama.lg.jp/documents/27806/kenchikukouji.pdf)）。→ 「品質管理」「工事写真・記録」「施工計画書」の補足説明の根拠。
- 建設キャリアアップシステム（CCUS）の能力評価は、保有資格・就労実績・知識技能で判定し、**職長・班長としての就業日数**が評価される。レベルは 1〜4、上位に登録基幹技能者（[国土交通省](https://www.mlit.go.jp/totikensangyo/const/content/001352984.pdf) など）。→ 「職長・班長の経験年数」を足す根拠。

### 3.2 現場に近い事務（現場事務・工事事務）

- 仕事の中心は、**工事原価・収支の管理**、法的書類の整備、社外との折衝、労務管理、現場事務所・宿舎の手配（[リクルートダイレクトスカウト](https://directscout.recruit.co.jp/job_descriptions/7148416)、[ビズリーチ](https://www.bizreach.jp/job/view/3456567/)）。
- 労災保険の申請、行政・発注者向けの書類作成。建設業の許可申請、安全書類、**産業廃棄物の届出**など（[en-ambi](https://en-ambi.com/job/j-15642360/)）。
- **再下請負通知書・施工体制台帳・施工体系図・作業員名簿**は、発注者向けの書類として、まとめて提出される。事務は、発注者の様式に合わせて整え、提出期限を管理する（[大阪府](https://www.pref.osaka.lg.jp/documents/137332/03_teisyutusyoruiitiransinkyutaihi0809.pdf)、[浜松市](https://www.city.hamamatsu.shizuoka.jp/documents/9351/20250331-20.pdf)）。
- CAD を使った図面確認や、3 次元 CAD の運用を担当する求人もある。普通自動車運転免許を求める求人もある。
- 資格: **建設業経理士**（1〜4 級。3〜4 級は建設業経理事務士）は、建設業の会計・原価計算の資格。1・2 級は経営事項審査の評価対象。日商簿記 2 級との範囲の重複が大きい（[ユーキャン](https://www.u-can.co.jp/course/data/in_html/1405/about/) など）。
- **確認できなかったこと**: 現場事務の求人で、建設業経理士などの資格を必須とする記述は、検索結果の範囲では見つからなかった。資格より、実務経験・事務処理能力が重視される傾向。

### 3.3 施工図を扱う人

- 施工図は、設計図を補って、**職人が作業順序を判断できる**ようにする図面。現場の作業員は、設計図ではなく施工図を主に見る。**施工者が作成し、設計事務所に承認を求める**（[CAD研究所](https://cad-kenkyujo.com/sikouzu/)、[日建連](https://www.nikkenren.com/kenchiku/jfcc_setsubi/info_sheet/pdf/Ⅶ-S-3.pdf) など）。
- 種類: **躯体図**（構造図を元に、柱・梁・壁・スラブの位置・寸法。躯体工事の前に作る）、**総合図（プロット図）**（意匠・構造・設備の情報を重ねて、納まりと干渉を確認し、合意形成する）、平面詳細図、断面詳細図、天井伏図、割付図、配管図、仮設図（足場・型枠・支保工）。
- スキル: CAD の実務経験（AutoCAD、Jw_cad、設備では T-fas など。3〜5 年程度を求める求人もある）。**BIM（Revit）は歓迎条件**として多い（3D は Revit、2D は AutoCAD という使い分けの例）。図面から情報を読み取る力、通り芯・高さの基準から寸法を設定する力。施工管理の知識も評価される。
- **確認できなかったこと**: 建築 CAD 検定の位置づけ。施工図を描く担当者の職種・資格の具体的な記述。

## 6. 判断してほしい点

1. **補足説明の方式**: A（入力の条件一覧に含める。推奨）か、B（動的スキーマ）か。
2. **カテゴリの再編**（§4）をするか。しない場合は、既存の 3 カテゴリに、新しい項目を入れる。
3. **件数**: 素案は、既存 39 件が約 75 件になる。多すぎる場合は、「新」のうち、根拠が「未」のものを外す。
4. **補足説明の文言**: LLM の判定に影響するので、採用するものは、**実際の職歴書での確認（T-M3-03）** で調整する。この素案は、叩き台。
5. 根拠が「未（検索で未確認）」の項目（建築CAD検定、2級電気／管工事施工管理技士、衛生管理者など）は、**公式資料で確認してから採用する**。
6. プリセットの補足説明を、画面から編集できるようにするか（MVP では、ファイルの編集のみを提案）。
